# cg-markdown Improvement Plan

**Component**: `cg-markdown`
**Category**: Foundation
**File**: `src/components/cg-markdown/cg-markdown.ts`
**Priority**: P1-High

---

## Executive Summary
**Overall Health**: Needs Work
**Top 3 Issues**:
1. XSS vulnerability: `.innerHTML` is used to inject parsed markdown (line 56) with no sanitization -- user-provided text could contain `<script>` tags or event handlers
2. Extensive use of magic numbers for spacing (`1em`, `0.5em`, `0.8em`, `0.4em`, `0.2em`, `2px`, `5px`, `3px`, `1.5em`) across lines 14-31
3. Font sizes use `rem` values (`1.5rem`, `1.25rem`, `1.1rem`, `0.85em`, `0.82rem`) instead of `--cg-font-size-*` tokens

---

## 1. Functional Issues

- **XSS vulnerability** (line 56): The `_render()` method converts markdown to HTML using regex, then injects it via `.innerHTML`. If `text` contains raw HTML like `<script>alert('xss')</script>` or `<img onerror="...">`, it will execute. The regex does not strip or escape HTML tags before processing markdown. Only the code block handler escapes `<` (line 38), but inline HTML passes through unescaped.
- **Regex-based parsing is fragile** (lines 37-52):
  - Nested bold/italic (`***text***`) is not handled.
  - Ordered list detection on line 50 (`m.includes('1.')`) is unreliable -- it checks the entire match for the literal string `1.` rather than checking the original markdown context.
  - Multi-line list items are not supported.
  - Consecutive blockquotes are not merged into a single `<blockquote>`.
  - Tables are not parsed (CSS exists for tables on lines 29-31 but no parsing logic generates `<table>` elements).
- **No paragraph wrapping for multi-line text**: The paragraph regex (line 51) only matches single lines that don't start with other block elements. Multi-line paragraphs with line breaks inside them are split into separate `<p>` tags.

## 2. Interaction Issues

### 2.1 State Coverage
- Component is purely presentational -- no interactive states.
- Links within rendered markdown have `:hover` style (line 24) -- good.

### 2.2 ARIA & Accessibility
- **Issue**: No `role` attribute on the `.md` container div. Consider `role="document"` or leaving it as generic div.
- **Issue**: Links generated by the parser include `target="_blank"` and `rel="noopener"` (line 45) -- good. But should also include `noreferrer`.
- **Issue**: Code blocks have no language indicator or `aria-label` for screen readers.
- **Issue**: No semantic heading hierarchy enforcement -- rendered h1-h3 may conflict with the page's heading structure. Consider a `headingOffset` prop.

### 3.3 Typography Token Usage
- **Critically under-tokenized**: Nearly all font sizes use raw `rem`/`em` values instead of `--cg-font-size-*` tokens.
- Font weights use raw numbers (`700`, `600`) instead of `--cg-font-weight-*` tokens (only the `th` rule on line 30 uses a token).
- Line height: Only `:host` and `pre` use tokens; headings and other elements inherit or are unset.

### 3.4 Modern Design Enhancements
- **Syntax highlighting**: For code blocks, consider integrating a lightweight syntax highlighter or at minimum adding language-specific `class` attributes.
- **Copy button on code blocks**: Modern markdown renderers include a "copy" button on code blocks.
- **Smooth reveal**: Add a fade-in for content appearing during streaming.
- **Table styling**: Add alternating row colors, hover states, and responsive horizontal scroll.

## 4. Prioritized Fixes

### P0 - Critical
1. **Fix XSS vulnerability**: Escape all HTML entities in input text BEFORE applying markdown regex transformations. At minimum, escape `<`, `>`, `&`, `"`, `'` first, then apply markdown patterns that generate trusted HTML tags.

### P1 - High
2. **Tokenize all font sizes** (lines 14-16, 20-21, 29): Replace `1.5rem`, `1.25rem`, `1.1rem`, `0.85em`, `0.82rem` with `--cg-font-size-*` tokens.
3. **Tokenize all font weights** (lines 14-16, 18): Replace `700`, `600` with `--cg-font-weight-*` tokens.
4. **Tokenize all margin/padding values** (lines 14-17, 20, 25-27): Replace `em`-based spacing with `--cg-spacing-*` tokens.
5. **Tokenize border widths** (lines 27, 30, 31): Use `--cg-border-width-*` tokens.
6. **Tokenize code padding** (line 20): Replace `2px 5px` with spacing tokens.

### P2 - Medium
7. **Fix ordered list detection** (line 50): Use a more reliable check than `m.includes('1.')`.
8. **Add `noreferrer` to link `rel`** (line 45).
9. **Add `headingOffset` prop**: Allow consumers to offset heading levels (e.g., h1 in markdown renders as h3 in DOM).
10. **Add table parsing**: CSS for tables exists (lines 29-31) but no markdown-to-table parsing is implemented.

### P3 - Low
11. **Add copy button to code blocks**: Modern UX expectation for code blocks.
12. **Support nested bold/italic**: Handle `***text***` patterns.
13. **Merge consecutive blockquotes**: Adjacent `> ` lines should form a single `<blockquote>`.
14. **Add syntax highlighting option**: Support a `highlight` boolean prop that adds language classes.

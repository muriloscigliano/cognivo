Text contrast passes WCAG AA wherever the components paint it, and the build checks every pair they actually use.

- **Tokens (existing palette shades, no new hue).** Light: muted text (`--cg-color-surface-container-outlined`, `--cg-color-input-text-placeholder`, `--cg-color-on-surface-container-default`, empty-state secondary) gray.500 → gray.600 (4.40 → 7.03:1 on the gray.100 page); accent text green.600 → green.800 (3.00 → 6.49:1); danger primary button text gray.900 → white on red (2.74 → 8.31:1); status text red/green/yellow 700 → 800 and status hover backgrounds 300 → 200 (hovered danger/status buttons and chips were 3.4–3.7:1); error hover-strong red.800 → red.900; code comments gray.500 → gray.400 (on the dark code background); the sidebar surface tokens are light in the light theme (they were black in both); `--cg-overlay-dark-text` is now defined in light too. Dark: muted text gray.600 → gray.400 (2.29 → 6.91:1 on cards), empty-state secondary and code comments gray.500 → gray.400.
- **Gate.** `validate-contrast` (runs on every tokens build) now derives the text/background pairs from every component's `css` template (226 pairs, both themes) instead of only a hand list: same-rule pairs, hover/active states paired with the element's resting colour, and text without a background checked against the page surfaces or the host background. `/* contrast: on --cg-color-… */`, `/* contrast: non-text */` and `/* contrast: decorative */` comments describe what CSS can't show. Known failures still to fix (twelve ai-* components and `cg-image-gallery`'s overflow badge) are listed with reasons in `scripts/contrast-baseline.json`, which can only shrink (see kit-fix-41 for its format). `contrast-gate.test.ts` in components re-runs the gate when component styles change.
- **Components.** Accent-coloured text used the primary *background* token (lime, 1.03:1 on white) in cg-autocomplete, cg-badge, cg-blockquote, cg-calendar, cg-command, cg-follow-up, cg-image-block, cg-listbox and five ai-* components; it is `--cg-color-accent-text` now. cg-tooltip error/success text uses the tooltip text colour (the variant keeps its coloured border); cg-navbar's badge sits on the primary background; cg-code-block's language chip and copy/expand hover use the code surface instead of a light hover; ai-data-preview / ai-prompt-template use on-primary text on primary buttons; ai-guardrail's danger hover and ai-action-receipt's compensate button are readable in dark.

*Visual change:* light-theme muted and accent text are darker; light-theme sidebars (`--cg-color-surface-sidebar-*`, e.g. `ai-app-sidebar`, `cg-app-shell`'s sidebar column) are light instead of black. Also: dark `--cg-color-surface-container-outlined` is gray.400 (was gray.600), so in dark `cg-avatar`'s border, ring and placeholder icon are lighter; light `--cg-color-empty-state-icon` is gray.500 (was gray.400), so `cg-empty-state`'s icon is darker. Status text and hover shades changed as listed above. These are part of the breaking visual changes in 2.0.0 (kit-fix-41).
